# Fluxion 需求文档

## 1. 项目目标

Fluxion 是一个优先面向 macOS 的 Tauri 文件下载应用。项目需要拆分为两部分：

- Fluxion Core：下载内核，提供协议无关的任务模型、调度、限速、持久化、事件通知和可扩展下载引擎。
- Fluxion App：基于 Fluxion Core 的 Tauri 桌面应用，提供现代化 UI、任务管理和下载状态可视化。

当前优先级：

1. 先实现 HTTP/HTTPS 多线程分块下载。
2. 再实现 BT 下载。
3. 后续扩展 FTP/SFTP 下载。
4. Chrome 插件作为 App/Core 能力成熟后的集成入口，用于接管浏览器下载和继承请求票据。

## 2. 范围定义

### 2.1 当前阶段范围

- macOS 桌面端。
- HTTP/HTTPS 下载。
- Tauri App 的任务创建、开始、暂停、停止、删除、列表查看。
- 全局下载限速和任务级下载限速。
- 是否使用系统代理的配置。
- 任务状态持久化和断点续传。

### 2.2 后续阶段范围

- BT 下载：种子文件、磁力链接、Tracker、UPnP、做种、反吸血、连接限制、分享率限制、IP 过滤。
- FTP/SFTP 下载。
- Chrome 浏览器插件：下载拦截、Cookie/Headers 继承、发送任务到 Fluxion App。
- 完整上传限速：主要影响 BT 做种和未来 P2P 能力。

### 2.3 非目标

- 第一阶段不实现 Windows/Linux 支持。
- 第一阶段不实现移动端。
- 第一阶段不实现云同步、多设备任务同步。
- 第一阶段不实现复杂队列规则，例如按站点、文件类型、时间段自动调度。

## 3. 用户角色

- 普通下载用户：希望稳定、快速地下载 HTTP/HTTPS 文件。
- 高级用户：需要自定义请求头、线程数、限速、代理和 Cookie 等下载参数。
- BT 用户：后续需要管理种子、磁力链接、选择文件和查看分块状态。

## 4. 功能需求

### 4.1 通用任务管理

每个下载任务需要支持：

- 创建任务。
- 开始任务。
- 暂停任务。
- 停止任务。
- 删除任务。
- 删除任务时可选择是否删除本地文件。
- 查看任务列表。
- 查看任务详情。
- 查看任务状态、进度、速度、剩余时间、错误信息。
- App 重启后恢复任务列表和任务状态。

任务状态至少包括：

- `Queued`：等待下载。
- `Resolving`：探测资源信息。
- `Downloading`：下载中。
- `Paused`：用户暂停。
- `Stopped`：用户停止。
- `Completed`：已完成。
- `Seeding`：BT 已完成后做种。
- `Failed`：失败。
- `Verifying`：校验中。

### 4.2 HTTP/HTTPS 下载

HTTP/HTTPS 下载需要支持：

- 自动跟随 301/302/303/307/308 重定向。
- 自定义请求头。
- Cookie、Authorization、Referer、User-Agent 等票据字段。
- 支持系统代理或关闭系统代理。
- 支持任务级代理配置扩展点。
- 自动探测资源是否支持 Range 分块下载。
- 支持多线程分块下载。
- 不支持分块时回落到单线程下载。
- 默认最大并发分块数为 16。
- 用户可配置单任务最大并发分块数。
- 支持断点续传。
- 支持 Content-Length 变化、ETag/Last-Modified 变化时的安全处理。
- 支持服务端不稳定时自动重试。
- 支持对 403、404、416、5xx 等状态码进行明确错误分类。
- 支持下载到临时文件，完成后原子移动到目标路径。

HTTP 探测规则：

- 优先发送 HEAD 请求，跟随重定向，读取最终 URL、Content-Length、Accept-Ranges、ETag、Last-Modified、Content-Disposition。
- 如果 HEAD 不可用或信息不足，发送 `GET Range: bytes=0-0` 探测。
- 只有服务端明确返回 `206 Partial Content` 且资源长度可确定时，才启用多线程分块。
- 如果资源长度未知、Range 不可用、服务端返回非 206、资源体积过小，则使用单线程下载。
- 如果已存在断点数据，需要校验 ETag、Last-Modified 或强校验信息；不匹配时要求重新开始或创建新文件。

### 4.3 限速

需要支持：

- 全局下载限速。
- 全局上传限速。
- 每个任务单独下载限速。
- 每个任务单独上传限速。
- 限速配置可运行时调整。

限速生效规则：

- 任务级限速不能绕过全局限速。
- 全局限速用于所有任务共享。
- 任务级限速用于单个任务内部所有连接共享。
- BT 后续需要同时消耗下载和上传令牌。

### 4.4 代理

需要支持：

- 全局配置是否使用系统代理。
- HTTP/HTTPS 下载遵守该配置。
- 为未来任务级代理预留配置字段。

macOS 系统代理读取可以放在 App 层或 Core 的平台适配层，Core 对外暴露抽象配置，不直接绑定 UI。

### 4.5 BT 下载

BT 下载后续需要支持：

- 创建种子文件任务。
- 创建磁力链接任务。
- 创建任务时选择需要下载的文件。
- 查看整体下载进度。
- 查看 piece 分块下载情况。
- 查看文件列表、单文件进度、单文件下载速度。
- Tracker list 配置。
- 全局自定义 Tracker list。
- UPnP/NAT-PMP 端口映射。
- 已完成任务做种分享。
- 分享率达到用户配置后自动停止上传。
- 最大连接数限制。
- 反吸血：支持屏蔽特定客户端连接。
- IP 黑名单和白名单。
- IP 过滤需要支持单个 IP 和 CIDR 子网。

BT 配置需要支持：

- 全局最大连接数。
- 单任务最大连接数。
- 全局 Tracker list。
- 单任务追加 Tracker list。
- 分享率停止阈值。
- 是否允许完成后自动做种。
- IP 黑白名单策略。
- 反吸血客户端规则。

### 4.6 FTP/SFTP 下载

FTP/SFTP 后续需要支持：

- URL 创建任务。
- 用户名密码认证。
- SFTP 私钥认证扩展。
- 断点续传。
- 单文件下载。
- 目录下载作为后续增强。
- 全局和任务级下载限速。

### 4.7 Chrome 插件

Chrome 插件后续需要支持：

- 拦截浏览器下载请求。
- 提取 URL、文件名、Cookie、User-Agent、Referer、Authorization 和其他必要 Headers。
- 将任务发送给 Fluxion App。
- 支持用户选择是否接管某次下载。
- 支持通过 Native Messaging 与 Fluxion App 通信。

安全要求：

- 插件只传递当前下载需要的最小 Headers。
- Cookie 等敏感字段只保存在本地，不上传。
- App 侧对来自插件的任务来源做校验。

## 5. 非功能需求

### 5.1 性能

- HTTP 多线程下载默认 16 并发分块。
- 下载过程避免把大文件加载到内存。
- 单连接读取缓冲建议 64 KiB 到 256 KiB。
- 写文件使用固定大小缓冲和位置写入，避免大量小对象分配。
- 任务状态更新需要节流，避免高频事件导致 UI 或数据库压力过高。
- 大文件下载时内存占用应主要随并发数和缓冲大小线性增长。

### 5.2 稳定性

- App 崩溃或退出后，重启可恢复未完成任务。
- 下载中断后可继续。
- 数据库写入要避免破坏已有任务状态。
- 完成文件需要校验大小，BT 任务需要 piece hash 校验。

### 5.3 可扩展性

- Core 使用协议引擎抽象，HTTP、BT、FTP、SFTP 都作为不同下载引擎接入。
- App 不直接依赖协议实现细节，通过统一任务 API 和事件订阅工作。
- 限速、代理、持久化、事件总线、任务调度作为 Core 的共享基础设施。

### 5.4 安全与隐私

- Cookie、Authorization 等票据需要加密或通过系统 Keychain 存储。
- 日志默认不输出敏感 Headers。
- 任务导出或诊断信息需要脱敏。
- 下载路径需要防止路径穿越。
- 打开文件和删除文件需要经过 App 权限边界。

### 5.5 可观测性

- Core 需要结构化日志。
- 任务失败需要包含可展示给用户的错误分类。
- Debug 模式可以导出任务诊断信息，但必须脱敏。

## 6. App UI 需求

Fluxion App 需要具备现代化、精心设计的 UI。第一阶段至少包括：

- 任务列表。
- 任务详情抽屉或详情页。
- 新建 HTTP 下载任务弹窗。
- 全局设置页。
- 下载状态、速度、进度、剩余时间展示。
- 批量开始、暂停、删除。
- 错误状态和重试入口。

HTTP 新建任务表单：

- URL。
- 保存目录。
- 文件名，可自动从 Content-Disposition 或 URL 推断。
- 自定义 Headers。
- Cookie 或票据输入。
- 最大线程数，默认 16。
- 任务限速。
- 是否使用系统代理。

BT 后续 UI：

- 添加种子文件。
- 添加磁力链接。
- 文件选择树。
- piece 分块进度视图。
- 文件列表速度和进度。
- 做种状态和分享率。

## 7. 数据需求

Core 需要持久化：

- 任务基础信息。
- 任务协议类型。
- 源 URL 或 BT 元信息引用。
- 保存路径。
- 文件名。
- 状态。
- 进度。
- 下载和上传速度快照。
- HTTP 最终 URL、Headers、ETag、Last-Modified、Content-Length。
- HTTP 分块范围和每块完成位置。
- 限速配置。
- 代理配置。
- 错误信息。
- 创建时间、更新时间、完成时间。

敏感字段：

- Cookie。
- Authorization。
- 私有 Token。
- SFTP 私钥密码。

敏感字段不应明文写入普通 SQLite 表；应优先使用 macOS Keychain，数据库只保存引用 ID。

## 8. 验收标准

第一阶段 HTTP 下载完成标准：

- 可以创建 HTTP/HTTPS 下载任务。
- 支持 302 跟随后下载最终资源。
- 支持自定义 Headers 和 Cookie。
- 可以自动判断是否支持 Range。
- 支持 Range 时使用最多 16 个分块并发下载。
- 不支持 Range 时自动单线程下载。
- 可以暂停并恢复下载。
- App 重启后可以恢复未完成任务。
- 全局下载限速和任务级下载限速有效。
- UI 能展示任务列表、状态、速度、进度和错误。
- 下载完成的文件大小正确，内容不因分块写入而损坏。

第二阶段 BT 下载完成标准：

- 可以通过种子文件和磁力链接创建任务。
- 创建时可以选择文件。
- 可以查看 piece 和文件级进度。
- 可以配置 Tracker、连接数、分享率、IP 过滤。
- 完成后可以做种，达到分享率后停止上传。
