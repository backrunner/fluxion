# Fluxion Releases

Fluxion publishes signed macOS updater bundles and DMGs to Cloudflare R2, exposed at
`https://assets.fluxion.alkinum.io`.

## Channels and tags

- Stable: `v1.2.3`
- Beta: `v1.2.3-beta.4`

The GitHub Actions workflow rejects other tag formats. Each channel has an independent
manifest, so beta releases never move the stable update pointer:

```text
releases/stable/<version>/...
releases/beta/<version>/...
updates/stable/latest.json
updates/beta/latest.json
```

## GitHub configuration

Create these repository secrets before pushing a release tag:

- `TAURI_SIGNING_PRIVATE_KEY`: contents of the private key generated by `cargo tauri signer generate`.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password for that key, if configured.
- `CLOUDFLARE_API_TOKEN`: API token with R2 object read/write access.

The non-secret Cloudflare account ID and `fluxion-releases` bucket name are committed in
the workflow. The bucket uses APAC placement and the custom domain requires TLS 1.2 or
newer.

The updater public key is embedded in `desktop/native/updater.rs`. Keep the
corresponding private key out of git; rotating it requires publishing a new app build
with the new public key before using the new signing key.

The workflow builds a universal `.app.tar.gz` updater artifact plus a DMG, generates
`latest.json`, uploads versioned files first, and only then updates the channel pointer.
The manifest exposes that same universal archive under both `darwin-aarch64` and
`darwin-x86_64`, which are the target keys requested by the native updater at runtime.

## Native build and signing

`python3 scripts/bundle-macos.py --release --universal --dmg` builds both Rust
architectures, combines them with `lipo`, bundles the embedded GPUI application,
and generates the app archive and DMG. It does not compile or embed a web frontend.
The standalone Tauri signer CLI is retained solely for compatibility with the
existing Minisign key and installed older releases; it is not an app dependency.

Set `APPLE_SIGNING_IDENTITY` to a Developer ID identity available on the build host.
Without an identity, the bundle is ad-hoc signed for local testing. The workflow
does not provision a signing certificate or perform Apple notarization: a public
Gatekeeper-ready release still requires those credentials and notarization on the
release host. Do not describe an ad-hoc build as notarized.

The native updater verifies the existing Minisign signature, restricts the update
host, validates archive paths, rejects links, verifies the extracted app signature,
and stages a replacement next to the installed app. Downloads pause and flush on
exit. A helper replaces the app after exit and retains the previous bundle in a
`.fluxion-update-*` directory for recovery. Installation needs write permission to
the app's parent directory. Live update installation should be tested using a
separately signed release before publication.
